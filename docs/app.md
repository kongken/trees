## 一、产品定位与核心概念

**产品一句话：**  
「把每年的目标种成一片森林」——用户通过设定年度目标、拆分行动，每完成一步，就让自己的树长高、长枝、长叶甚至结果。

**核心功能目标：**  
- 帮用户**记录和回顾每一年的目标**（年度级别为主，兼顾季度/月度拆解）
- 用「种树 / 养树」的可视化过程，**持续提醒、激励**用户执行目标
- 通过**年复一年的森林**，建立「人生时间线」的仪式感和成就感

***

## 二、世界观与隐喻设计：目标 = 树，人生 = 森林

为避免只是「换个皮的 ToDo」，需要把「树」这个隐喻做深做透：

- **一棵树 = 一个年度大目标**
  - 例：2026 年目标「升职为资深工程师」 → 一棵树
- **主干 = 关键路径 / 大里程碑**
  - 例：3 个关键节点：拿到一个高难度项目、主导一次技术分享、通过绩效评估
- **大枝 = 子目标 / 项目**
  - 如「完成 A 项目」「系统化学习 XX 技术」
- **叶子 = 具体行动 / 任务**
  - 如「每周阅读 2 篇技术文章」「每月写一篇技术博客」
- **果实 = 阶段性成果 / 证据**
  - 如「拿到某证书」「发布一篇被大量点赞的文章」「体重达成目标前后对比照片」

**一年 = 一个「林地」**  
- 一个年份对应一块地，里面可能有多棵树（工作、健康、财务、人际、兴趣等不同目标）
- 多年叠加形成「人生森林」，可横向滑动浏览 2024、2025、2026…的变化

## 三、用户核心体验流程（Core Loop）

### 1. 年度开启（种下种子）

- 打开 App，选择「开始我的 20XX 年」  
- 引导用户用 1–3 句话写下当年的**年度主题句**（例如「变得更健康」「向管理者迈进一步」）
- 系统推荐几个**目标分类模板**：
  - 健康、事业、财务、学习、人际、兴趣 / 你也可以自定义分类
- 每创建一个年度目标 → 自动生成一颗「小树苗」

> 设计要点：控制首次设置的目标数量（比如推荐 3 个核心目标即可），避免一开始就过重，导致放弃。

### 2. 拆解成可执行行动（长出枝叶）

在目标详情页（对应一棵树）：

- 第一步：设定该目标的**成功定义**（一句话）
- 第二步：添加 3–5 个**关键里程碑**（对应树干上的节点）
- 第三步：每个里程碑下添加**子目标/习惯/任务**（对应树枝和叶子）
  - 子目标可以是：
    - 习惯型（例如「每周三次健身」）
    - 一次性任务（例如「报名雅思考试」）
    - 截止日期任务（例如「6 月前完成作品集」）

App 依据拆解程度，动态让树**从树苗长到小树**，对用户形成即时正反馈。

### 3. 日常打卡（浇水、施肥、晒太阳）

用户每天/每周的主要操作：

- 打开「今日 / 本周」页面，自动汇总**当前进行中的所有树的待办事项**
- 用户完成一个任务：
  - 点击「完成」，系统给出**即时视觉反馈**：
    - 这棵树长高一点、长出一片新叶、或结出一个小果实
    - 同时给出简短鼓励文案
- 若用户连续多天完成与某棵树相关的任务：
  - 出现「连续浇水 X 天」「树长势良好」等状态贴纸
- 若长时间未对某个目标做任何行动：
  - 树会呈现**轻微枯萎 / 落叶**的视觉效果，但不会「完全死掉」，更多是一种温和提醒

### 4. 阶段回顾（给树拍照、写年轮）

- 每月 / 每季度，系统主动弹出「树的生长记录」：
  - 显示本阶段完成了多少任务、达成了哪些里程碑
  - 提醒用户为这棵树写一段**成长日志**（对目标进展的复盘与感受）
- 年度末：
  - 显示这一年的「整片林地」：哪些树长得茂盛、哪些停留在树苗状态
  - 用户可以给每棵树添加一段「年轮日志」（今年这个目标的总结）
  - 引导用户为下一年**决定保留、移植、砍掉或新种**哪些目标树

## 四、信息架构与主要页面

### 1. 首页 = 年度森林视图

- 默认显示当年（如 2026）的「鸟瞰图」：
  - 每个目标一棵树，按分类分区域（工作区、生活区、学习区…）
  - 树的大小、繁茂程度与该目标完成度、行动频率挂钩
- 顶部可以左右滑动切年：2024 | 2025 | 2026
- 下方有一个「今日待办 / 本周重点」的简要条

用户动机：一打开就能看到「这一年的生活长成什么样」。

### 2. 目标详情页 = 单棵树的近景

包含：

- 树的 3D / 2.5D 形象（或风格化插画）
- 目标标题 + 成功定义 + 分类标签
- 一个「里程碑时间轴」：
  - 节点对应树干上的横切点：里程碑标题 + 预计时间
- 当前待办任务列表（叶子）
- 底部一个「成长日志」Tab：按时间轴展示完成记录和用户写的感想

交互小细节：

- 完成一个里程碑时，播放树**明显长高**的短动画，增强仪式感
- 每次打开树页面，随机展示最近的一句「树语」（可以是系统文案，也可以是用户的自我激励语）

### 3. 日 / 周行动页

与普通待办工具的区别是：

- 所有任务都带有**树的头像 / 颜色**，一眼看出是为了哪棵树、哪个目标
- 可按「树」分组查看：「今天我主要在浇哪几棵树？」
- 完成多个任务后，会有「今日浇水报告」：
  - 给出总共让多少棵树长高、增加多少叶子

### 4. 年度回顾页

结构建议：

- 顶部：一句话总结（系统自动生成，如「你在 2026 年种下了 5 棵树，其中 3 棵长成了大树」）
- 中部：该年森林的前后对比：
  - 年初 vs 年末的视觉对比（可以存两张截图式快照）
- 下方：按类别展示：
  - 工作树：完成度 X%
  - 健康树：完成度 X%
  - 学习树…
- 最后：引导用户为下一年设置 1–3 个「关键树」，将注意力集中

## 五、功能细节设计：如何让“树”真正驱动行为

### 1. 目标设定的「低门槛」

避免一上来就问太多字段，可以采用**逐步引导**：

1. 先写一句「我今年最想达成的是什么？」
2. App 自动给几个「建议问题」帮用户澄清：
   - 为什么这对你重要？
   - 如果年底回头看，什么结果会让你觉得满意？
3. 再用简单模板生成目标结构：
   - 帮用户拆成 2–3 个里程碑的草稿
   - 用户可以再微调

### 2. 可视化进度映射到树的变化

可设计一套简单规则：

- 目标完成度 0–25%：小树苗
- 25–50%：小树
- 50–75%：有较多枝叶
- 75–99%：有果实
- 100%：树冠饱满 + 特殊光效 / 徽章

任务粒度建议：

- 一个普通任务完成 → +少量成长值（例如让一片叶子变绿）
- 关键里程碑完成 → 树整体升级一个阶段

### 3. 温和的失败反馈

不建议设计「树死掉」这种强惩罚（容易打击用户），可以采用：

- 很久没行动：树叶有一点点发黄 + 提示「这棵树有点渴了，来浇浇水？」
- 用户主动放弃/删除目标：
  - 提供选项：「把这棵树移到『休眠林地』」而不是直接砍掉
  - 用户多年后仍可回看，形成一种真实的人生呈现：「有些目标曾经很重要，但后来选择放下了」

## 六、激励与成长系统（类游戏化设计）

可以借鉴已有的种树类产品在动机设计上的成功经验，如 Forest 将「专注时间」用树的生长和森林可视化展示，结合积分与解锁新树种，提高持续使用意愿。 [goodux.appcues](https://goodux.appcues.com/blog/forests-gamified-focus)

围绕年度目标，可以设计：

### 1. 种类解锁

- 初始只有几种基础树（松、橡树、樱花…）
- 随着用户：
  - 连续坚持某目标 X 天
  - 年度完成核心目标
  - 写满一定数量的成长日志
- 解锁更稀有的树种（银杏、红枫、古树等），附带专属视觉风格

### 2. 徽章系统

徽章围绕「年份 × 树 × 行为」设计：

- 「守护者」：一年内持续为同一棵树浇水超过 100 天
- 「专注之林」：某一年 80% 以上的树完成度超过 70%
- 「勇于放下」：主动将一棵长期拖延的树迁入“休眠林地”，并写下复盘

### 3. 社交与共享

轻度社交即可，不必强社交：

- 分享「我的 20XX 森林截图」到朋友圈 / 社交媒体
- 可以开启「私密」或「公开」模式：
  - 公开模式下，标题可见，细节可只对自己展示
- 好友间可以互相「参观森林」：
  - 点赞某棵树，留下一句鼓励

***

## 七、隐私与情感安全

由于年度目标涉及个人隐私（收入、健康、情感等），需要重点考虑：

- 默认所有目标对外**不可见**，用户主动选择分享才会暴露部分信息
- 分享时可以选择：
  - 仅分享「树的外观 + 类别」，不显示具体目标内容
- 提供「快速锁定」功能：
  - 开屏或切换 App 时，可以设置需要 Face ID / 指纹解锁后才能进入森林界面

## 八、技术与实现上的简要建议

### 1. 数据模型（概念级）

- Year
  - id, yearNumber, themeSentence
- GoalTree
  - id, yearId, title, category, successDefinition, createdAt, status, progress
- Milestone
  - id, treeId, title, dueDate, completedAt, order
- Task
  - id, milestoneId (或 treeId), title, type (habit / once / deadline), repeatRule, dueDate, completedAt
- Log
  - id, treeId, content, createdAt, type (系统记录 / 用户日志)

### 2. 动画与表现层解耦

- 逻辑层只维护一个「成长值」或「进度等级」
- UI 层根据该数值选择对应的树状态（多套插画 / Spine 动画帧）
- 便于后期迭代更多树种或换美术风格

## 九、一个简单的「第一页原型」构想（文字版）

**页面：2026 年首页**

- 顶部：  
  - 左：年份选择（< 2025 | 2026 | 2027 >）  
  - 右：统计按钮（本年完成度 62%）
- 中间：一块横向可滑动的「林地」：
  - 左边一棵高大的树（标题：『升职为资深工程师』进度 75%）
  - 中间一棵枝叶繁茂带果实的树（『体脂降到 18%』进度 90%）
  - 右边一棵中等大小的树（『每月读一本书』进度 40%）
- 下方卡片：「今天可以做的 5 件小事」：
  - [体脂树] 今天打卡健身 30 分钟
  - [升职树] 看完一篇技术文章并做笔记
  - [阅读树] 阅读书籍 20 页
- 底部导航：
  - 森林 | 今日 | 统计 | 我
